# ADR-001 — Autenticação, autorização e proteção CSRF

- **Status:** adotada no projeto acadêmico; revisada em 12/11/2026 após alertas de segurança do SonarQube Cloud.
- **Contexto:** o sistema possui quatro perfis: `SOLICITANTE`, `PROFESSOR`, `RESPONSAVEL` e `ADMINISTRADOR`. Há interface de login por formulário, sessão de navegador, chamadas `fetch` e autenticação HTTP Basic para a API.
- **Identidade:** usuários persistidos em PostgreSQL, senhas com BCrypt, primeiro administrador inicializado por variáveis de ambiente, cadastro institucional de professor sujeito a ativação. Sessões são criadas conforme necessário (`IF_REQUIRED`).
- **Permissões:** apenas administrador gerencia usuários/recursos/manutenção; apenas responsável aprova/rejeita reservas e registra retirada/devolução de materiais. O responsável não pode avaliar sua própria solicitação. Solicitante/professor só consulta e altera suas reservas, respeitando as regras de estado. Relatórios permitidos a administrador e responsável.
- **CSRF:** habilitado por padrão para **todos os perfis**, incluindo homologação local. Operações que modificam estado exigem token. `GET /csrf` disponibiliza token de sessão a formulários e ao JavaScript. O login envia o token como parâmetro oculto; cadastro/confirmacao, ações da página principal e logout enviam o token como cabeçalho/parâmetro conforme o caso. O token é vinculado à sessão HTTP, que deve ser preservada pelo cliente.
- **Chamadas externas HTTP Basic:** para verbos de mutação, o cliente deve primeiro consultar `GET /csrf`, preservar o cookie de sessão e enviar o token em `X-CSRF-TOKEN`. Leituras GET continuam acessíveis conforme autenticação e papel; sem token, a mutação é recusada com HTTP 403.
- **Carga JMeter:** o plano `jmeter/reservas-concorrentes.jmx` foi adaptado para obter o token e guardar cookie por thread. A evidência de carga antiga precede a mudança: **reexecutar o cenário** antes de afirmar que os números continuam idênticos.
- **Segurança operacional:** HTTP Basic e cookies de sessão exigem HTTPS fora de `localhost`, gestão segura dos segredos e revisão de configuração. Proteção CSRF não substitui controle de acesso, validação, proteção XSS nem análise de dependências.
- **Verificação:** usar `CsrfPerfilPadraoTest`, `CsrfProducaoTest`, `AutorizacaoApiTest` e `FluxoCompletoE2ETest`; confirmar CI, análise SonarCloud e teste manual de login/cadastro/reserva na instância isolada :8085 antes da integração à `main`. Não atualizar a instalação original :8080 durante homologação.
